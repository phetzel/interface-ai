# Architecture

Interface AI implements one read-only savings lookup on a synthetic banking app. Python owns discovery, policy, native input, local vision/OCR and replay; React/TypeScript supplies the test application. A Linux ARM64 container runs one sandboxed Chromium window on a 1280×800 X11 desktop. Both automation and the operator see that framebuffer. The native calibration pad separately proves that input is not tied to a browser DOM.

The host accepts a bounded natural-language savings goal, typed member ID and approved target (`synthetic-bank` or `http://fixture:4173/`). Unsupported intents, targets and inconsistent IDs fail before credentials, reset or model use. OpenAI Responses chooses actions from admitted screenshots; the prompt supplies no ordered UI path. A guarded desktop worker validates every proposed primitive against the current screen and ownership epoch. Exact identity and a locally parsed savings result determine completion; model prose cannot supply a balance. Discovery is bounded by 20 requests, 40 inputs, four batch items and 120 seconds, with no implicit provider retries.

CLI replay, the operator panel and discovery share one coordinator and OS adapter. The provider key and optional SDK remain on the host. Replay has neither, and its container cannot reach the provider. This makes the normal execution path cheap and inspectable. The cost is a deliberately narrow supported environment rather than arbitrary application access. Docker is the tested distribution; a host wheel and other operating systems are not claimed.

# Artifact schema

A capability contains separate schema/capability versions, typed inputs and outputs, ordered actions, visual targets, extraction fields, checkpoints, environment assumptions and digest-bound assets. Member IDs are five-character strings, preserving leading zeroes; money is an integer number of minor units plus currency. Results distinguish `success`, `business_outcome` and `failure`. Pydantic models publish six JSON Schemas, checked for drift during validation.

The recorder converts **executed** discovery inputs into a version-2 candidate. Each action references observation/trajectory provenance; the typing action becomes a named `memberId` binding. Clicks become offsets from reviewed visual anchors. The real recorded example has four input actions plus local extraction, compared with the earlier manual artifact's five inputs. Environment, OCR fields and checkpoint semantics come from a reviewed bank profile; the missing-member branch was reused, not observed in the successful discovery. These derivations are explicit.

A candidate cannot authorize itself. Separate operator-owned promotion manifests bind its exact bytes, asset digests, provenance, allowed identifiers and continuation boundary. Candidate evaluation replays member B on default and translated layouts before approval. The checked-in promotion is **agent-reviewed**, with identical candidate/approved hashes and no hidden action edits. Manifests provide trusted-local admission, not cryptographic protection from a malicious host. The bounded registry allows eight approvals, not a general workflow platform.

# Determinism & error handling

Replay uses OpenCV template matching, relative regions and pinned Tesseract OCR. It verifies declared pre/postconditions and the original member identity before returning output. It rejects ambiguous matches and invalid amounts rather than guessing. Bounded polling handles slow transitions; observations may be retried, uncertain input is never blindly replayed. The supported translation moves content 40 pixels on both axes; this is evidence for that variation, not arbitrary layout or display-scale robustness.

Invalid inputs fail before dispatch. A missing member is a named business outcome. Session expiry requests intervention; unknown checkpoints, unreadable output, permission/policy denial and timeouts stop with distinct codes and step context. Routine events retain action purpose, target, checkpoint, expected/observed categories and policy decisions. This sanitized trace is the richer failure diagnostic; full screenshots and raw OCR are not necessary to debug the tested failures. The UI exposes the current live screen. Explicit synthetic business results are stored separately from routine/exported metadata.

Artifact loading reads bounded regular-file snapshots, verifies digests and decodes those same bytes, rejecting unsafe paths and symlinks. Build manifests bind executable source to shipped image bytes. The retained evidence covers genuine discovery, second-member reuse, negative cases, repeated replay, Stop, and source/image identity. Automated operators and genuine provider calls are labeled separately; a test oracle exists only in the host harness, never in runtime execution.

# Heterogeneity & multi-tenant

The adapter's observe/input interface and the artifact's declarative targets/checkpoints separate a flow from surface mechanics. Today both browser and native input use OS events; bank recognition remains specific to its approved visual profile. A legacy web or native application could add an approved accessibility/visual recognizer and operation policy behind that seam. Supporting its input primitives alone would not make this bank artifact work on it.

For tenant reuse, I would keep a vendor/workflow base capability separate from a versioned tenant binding: approved entry point, application identity, locale, display requirements and restricted label/anchor overrides. Credentials would be session-scoped secrets, never artifact parameters. Every binding would have its own digest, policy review and replay evidence. Overrides could specialize targets, not silently weaken identity/output checks or broaden action authority. A startup compatibility check and checkpoint failures would quarantine an incompatible binding; a recorded revision would require review before replacing it. Scheduling and tenant-isolated desktops can be added around the existing invocation/session boundary. Multi-tenant routing, override resolution and fleet drift management are design proposals, not implemented features.

# Escalation & handoff

The coordinator exposes intervention reason, current step/checkpoint and live desktop at loopback port 6081. An ownership epoch invalidates old automation/model responses. Takeover first quiesces input through a lock barrier, then grants the human exclusive control through the same adapter. The panel records human action metadata without retaining typed text or keys. Stop signals cancellation before acquiring the coordinator mutex, so pending typing cannot block it. Terminal results are finalized once and cannot overwrite Stop; storage failures revoke input.

Automatic continuation is intentionally restricted to the independently approved search-completion → original-member overview → open-Savings boundary. Resume rechecks the screen and exact member; wrong screen/member leaves human ownership intact. Recovery preserves the session UUID and does not repeat completed automation input. Arbitrary interruptions, including discovery takeover, permit inspection but require reset rather than inventing a continuation. Human control is bounded by 15 minutes and an action limit. The earlier real-person manual-artifact recovery and the generated-artifact simulated handoffs have distinct evidence; the final personal review remains the author's responsibility.

# Safety

An explicit allowlist is split between trusted configuration and code: approved target/entry point, manifest-bound capabilities/assets, allowed native operations, visible control/state checks, fixed application identity, gateway routes and Chromium navigation policy. Operators change these deliberately and rebuild/revalidate; a model or artifact cannot expand them. Automation permits the reviewed lookup only. Transfers, settings, unrelated coordinates and other risky actions are denied before dispatch. Human recovery has broader native input within the isolated synthetic application, not an unrestricted production banking authorization claim.

The non-root desktop has no default network route, host home, Docker socket, provider key or fixture oracle. A narrow gateway serves the fixture; only the operator relay publishes loopback 6081. Host/Origin/token and lease checks protect control requests. Raw model conversations and full frames remain in memory. Candidate staging retains only reviewed static-label crops, with bounded files and explicit promotion. Sanitized export reconstructs an allowlisted metadata shape and excludes business values. `store: false` controls response storage but does not promise zero provider retention. A malicious host or application that imitates trusted pixels is outside this PoC's trust boundary.

# Cuts

The complete vertical slice is one bank workflow, one target and one fixed locale/display. Natural-language admission uses a small documented grammar, not general intent understanding. There is no unrestricted recorder, tenant service, credential vault, distributed queue, arbitrary recovery, accessibility backend or model-assisted replay. The operator supports fit/actual-size viewing and explicit text/key controls; it is not a production co-browsing console. Source/image checks do not make independently rebuilt OS packages bit-for-bit reproducible.

Next I would use reviewer feedback to improve human-control ergonomics, then validate one second vendor/tenant profile before adding infrastructure. The final setup rehearsal, requirement coverage and evidence pointers are indexed in [the submission review](docs/ASSESSMENT_CHECK.md); [the demo guide](docs/DEMO.md) gives the exact commands. The focus is a traceable discovered capability, deterministic reuse and a real ownership boundary.
